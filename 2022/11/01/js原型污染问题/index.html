基础知识

1、js 中的 prototype、proto

  • JavaScript 是基于原型的继承模型。构造函数有一个 prototype 属性，实例对象内部通过 [[Prototype]] 指向其原型对象；
  • 实例对象并不是“拥有”原型上的所有变量和方法，而是在自身属性找不到时，沿着原型链向上查找；
  • 访问原型的方式：
    • 构造函数：
      • Foo.prototype
    • 实例对象：
      • foo.__proto__
      • foo.constructor.prototype
  • __proto__ 是历史遗留访问器，实际开发中更推荐使用 Object.getPrototypeOf(foo) 和 Object.setPrototypeOf(foo, proto)；foo.constructor.prototype 也不总是可靠，因为 constructor 属性本身可能被覆盖。

2、原型链继承

js 使用 prototype 链实现继承机制

3、原型链污染

由于 js 原型链继承机制，如果攻击者控制并修改了一个对象的原型，可影响所有链上的对象，例如：来自同一个类的对象；

4、常见的原型链污染场景

核心问题是：攻击者能否控制对象属性路径，并让程序把这些属性写入普通对象或其原型链。

  • 深合并/默认值合并：merge(target, source)、defaultsDeep 等递归合并函数，如果没有过滤危险 key，可能把 __proto__、constructor.prototype 写入原型链；
  • 路径赋值：set(obj, 'a.b.c', value) 这类函数如果路径可控，攻击者可构造 __proto__.polluted、constructor.prototype.polluted；
  • 反序列化/解析：JSON、querystring、YAML、表单参数等外部输入被解析成对象后，如果直接进入合并或路径赋值逻辑，就可能触发污染；
  • 模板/框架配置：污染本身通常只是写入属性，真正造成 XSS、鉴权绕过、RCE 还需要后续代码读取这些被污染属性，也就是需要可利用的 gadget。

注意，{"__proto__": {...}} 写在 JavaScript 对象字面量里时通常会触发 __proto__ 的特殊语义；而通过 JSON.parse 解析时会得到一个普通自有属性名为 __proto__ 的对象。这个对象本身还不一定污染原型，真正危险的是后续不安全的递归合并/赋值逻辑：

原型污染利用链通常可以拆成两步：

  • 污染入口：攻击者控制 key/path/value，把属性写到 Object.prototype 或其他共享原型上；
  • 触发点：业务代码、模板引擎或库代码读取该属性，并把它用于敏感逻辑，例如命令执行参数、模板编译参数、鉴权判断、文件路径、HTTP 头等。

原型链基础了解，可直接参考：https://www.leavesongs.com/PENETRATION/javascript-prototype-pollution-attack.html

SquirrellyJS 远程代码执行（CVE-2021-32819）

https://blog.diefunction.io/vulnerabilities/ghsl-2021-023

SquirrellyJS (https://github.com/squirrellyjs/squirrelly) 是一个用 js 编写的模板引擎。

漏洞描述：

Express 渲染 API 原本用于传递模板数据，但 Squirrelly v8 会把模板数据和引擎配置选项混在同一个对象里处理。若应用直接把 req.query、req.body 等用户可控对象传给 res.render()，攻击者就能通过查询参数控制 defaultFilter、autoEscape 等配置项。模板编译阶段会把 defaultFilter 拼接进生成的函数源码，从而造成 RCE。

严格来说，CVE-2021-32819 不是典型的 __proto__ / constructor.prototype 原型污染，而是“用户可控配置项注入”。它和前文原型污染案例的相似点是：攻击者污染了模板编译阶段会读取的配置，最终借助模板引擎的动态代码生成能力触发执行。

影响版本：

  • 受影响版本：SquirrellyJS v8.0.0 到 v8.0.8，包括部分 v8.0.0-beta.*
  • 修复版本：9.0.0 或更高版本

根据 NVD/OSV 和 GitHub Security Lab 资料，该问题已在 9.0.0 修复；截至本文修订时 npm 上的 9.1.0 不属于该 CVE 的受影响版本。

修复与防护

原型污染漏洞的修复重点不是只过滤一个 __proto__，而是阻断所有能写到原型链的危险路径：

  • 对外部输入做 schema 校验，拒绝未知字段，尤其是对象递归结构、路径字符串和配置对象；
  • 在深合并、clone、路径赋值函数里显式拦截 __proto__、prototype、constructor 这几个 key；
  • 避免把 req.query、req.body、反序列化结果等用户可控对象直接传给模板引擎、配置合并函数或 Object.assign/深合并函数；
  • 配置对象优先使用白名单字段拷贝，而不是“把用户对象整体 merge 进去”；
  • 对纯字典数据可使用 Object.create(null) 或 Map，减少从 Object.prototype 继承污染属性的风险；
  • Node.js 运行时可考虑 --disable-proto=delete 或 --disable-proto=throw 降低 __proto__ 攻击面，但这不能防住 constructor.prototype 路径，也不能替代代码层面的过滤；
  • 依赖库及时升级，尤其是 lodash、hoek、handlebars、Squirrelly 等历史上出现过污染入口或可利用 gadget 的库。
