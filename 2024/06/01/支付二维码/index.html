支付二维码标准：QR Code、EMV QR Code、SGQR 与 QRIS

二维码与 QR Code

二维码是对一维条码的一次扩展：一维条码主要在单一方向上编码信息，二维码可以在水平和垂直两个方向上编码，因此在相同面积内能承载更多数据。

需要注意的是，”二维码”是一个大类，QR Code 只是其中一种二维条码。常见二维条码还包括 PDF417、Data Matrix、MaxiCode、Aztec 等，不同码制在容量、识读速度、纠错、适用场景上各有差异。

QR Code 由日本 DENSO WAVE 发明。DENSO WAVE 公开了 QR Code 规格，并声明对标准 QR Code 不行使其持有的专利权。QR Code 在 2000 年 6 月被采纳为 ISO 国际标准 ISO/IEC 18004；不过 ISO/IEC 18004:2000 已经被后续版本取代，当前可查询到的 ISO 正式版本是 ISO/IEC 18004:2024。

标准 QR Code 的规格要点：

  • 符号尺寸从 21 x 21 到 177 x 177 码元，每提升一个版本，边长增加 4 个码元。
  • 最高容量取决于版本、纠错等级和编码模式。DENSO WAVE 给出的最大值为：数字 7,089 个、字母数字 4,296 个、8-bit 字节 2,953 个、汉字 1,817 个。
  • 纠错等级分为 L/M/Q/H，约可恢复 7%/15%/25%/30% 的码字。

后来，支付宝、微信支付等把 QR Code 广泛应用到移动支付领域，形成了”用户扫商户码”和”商户扫用户码”两类常见产品形态。

QR Code 也在不断演进。为了更小尺寸，有 Micro QR Code；为了更高容量和更多形态，有 iQR Code；为了受控读取，有 SQRC 等。注意：这些扩展码制的开放程度、商标和专利策略不完全等同于标准 QR Code，实际落地前需要确认相应规格和授权条件。

EMV QR Code

背景

QR Code 只是信息载体，本身不定义支付字段。一个二维码里可以放 URL、文本、名片，也可以放支付参数。EMV QR Code 则是在 QR Code 载体之上，为支付场景定义的一套结构化数据格式。

EMVCo 是维护 EMV 相关规范的技术组织。EMV 最初来自 Europay、Mastercard、Visa 三方的芯片卡支付规范；EMVCo 于 1999 年成立。现在 EMVCo 已不是”两大卡组织”维护的组织，而是由 American Express、Discover、JCB、Mastercard、UnionPay 和 Visa 六个成员组织共同拥有和管理。

EMVCo 维护的支付交互标准包括接触式芯片、非接触式、Tokenisation、Mobile EMV、3-D Secure、Secure Remote Commerce，以及 EMV QR Code 等。

EMV QR Code 规范分成两种场景：

  • 《EMV QR Code Specification for Payment Systems (EMV QRCPS) Consumer-Presented Mode》
  • 《EMV QR Code Specification for Payment Systems (EMV QRCPS) Merchant-Presented Mode》

中文可以理解为：

  • CPM（Consumer-Presented Mode，用户出示码）：付款人展示二维码，商户或收银设备扫描。国内通常称为”被扫”或”付款码”。
  • MPM（Merchant-Presented Mode，商户出示码）：商户展示二维码，消费者用钱包 App 扫描。国内通常称为”主扫”或”收款码”。

这里容易混淆：MPM 才是消费者主动扫码付款，CPM 是消费者出示付款码被商户扫描。

EMVCo 在 2017 年公开发布 QR Code 支付规范。官方规范页目前列出的公开版本为 CPM v1.1 和 MPM v1.1，发布时间均为 2020 年 11 月 27 日；此外还有若干规范公告（Specification Bulletin），实现时应同时关注。

规范下载地址：

  • EMVCo QR Codes
  • EMV QR Code Consumer-Presented Mode v1.1
  • EMV QR Code Merchant-Presented Mode v1.1

原文附件：

EMV MPM 的数据对象采用 ID + Length + Value 结构，通常也会被口语化称为 TLV：

  • ID：2 位数字，表示数据对象编号。比如 00、01、52、63。

几个核心字段说明：

ID 名称 说明
00 Payload Format Indicator 固定为 01。
01 Point of Initiation Method 11 表示静态码，12 表示动态码。
02-51 Merchant Account Information 商户账户信息。02-25 通常为支付组织保留区，26-51 可按模板扩展；模板内的 00 一般是 Globally Unique Identifier。
52 Merchant Category Code 商户类别码，通常按 ISO 18245 MCC。
53 Transaction Currency 交易币种，使用 ISO 4217 数字币种代码，例如人民币为 156。
54 Transaction Amount 交易金额。静态码可以不带金额，由用户输入；动态码通常会带金额。
58 Country Code 商户国家/地区，使用 ISO 3166-1 alpha-2，例如中国为 CN。
59 Merchant Name 商户名称。
60 Merchant City 商户城市。
62 Additional Data Field Template 附加数据模板，可放订单号、账单号、终端号等子字段。
64 Merchant Information Language Template 多语言商户信息模板，例如中文商户名和城市。
63 CRC CRC-16/CCITT-FALSE 校验值。
80-99 Unreserved Templates 未保留模板，供支付方案或实现方扩展。

EMV QR Code 校验码

63 代表 CRC 校验值。它不是数字签名，也不能证明二维码”没有被恶意篡改”；它只能用于发现 payload 与 CRC 不匹配的情况。攻击者如果能修改 payload，也可以重新计算 CRC。因此，支付 App 不能把 CRC 当作防伪机制，商户身份、收款账户、金额等关键数据仍应通过支付网络、收单方或服务端可信记录校验。

EMV MPM 的 CRC 计算规则可以概括为：

  • 算法：CRC-16/CCITT-FALSE。
  • 初始值：0xFFFF。
  • 多项式：0x1021。
  • 计算范围：从 payload 开头一直到 6304，不包含最终 4 位 CRC 值。
  • 输出格式：4 位大写十六进制字符，不足 4 位左侧补 0。

SGQR

Singapore Quick Response Code（SGQR）是新加坡统一的支付二维码标签标准。它不是一个单独的钱包 App，也不是一个新的支付方案；它把多个电子支付方案整合到同一个 SGQR 标签中，消费者通过标签上的支付方式标识判断自己的钱包是否可用。

SGQR 基于 EMVCo 的 Merchant-Presented Mode 规范，并针对新加坡市场做了本地化约束，例如新加坡相关字段的位置、EMV 字段使用指导，以及多个支付方案在 Merchant Account Information 中的排列和编码效率。

需要修正原文中一个容易误解的说法：”一个 SGQR 可同时被支付宝、微信等支付方式扫描解析”并不表示任意支付宝或微信钱包都能扫任意 SGQR 成功付款。实际能否支付取决于：

  • 该商户的 SGQR 标签中是否包含对应支付方案；
  • 用户钱包是否支持该方案和当地跨境规则；
  • 收单方、支付方案和钱包之间是否完成商业和技术接入。

SGQR 商户名篡改风险

原文提到的 SGQR 漏洞，本质上不是 QR Code 或 CRC 算法漏洞，而是支付 App 的信任边界问题。

如果钱包 App 在付款确认页直接展示二维码 payload 里的 59（Merchant Name），而不是从支付方案、收单方或商户注册记录中校验并展示商户名称，攻击者就可能篡改 59 字段、重新计算 CRC，并生成一个外观看似合法的 SGQR，让用户以为自己正在向真实商户付款。

防护要点：

  • App 可以解析并校验 CRC，但不能信任 CRC 作为防篡改证明。
  • 商户名称、收款账户、商户 ID、金额等关键展示信息应来自可信后端或支付网络返回结果。
  • 对静态商户码，应校验码中支付方案账号与注册商户记录的一致性。
  • 对动态码，应将金额、订单号、商户标识与服务端订单状态绑定，避免只信任二维码本地字段。

QRIS

QRIS 的官方全称是 Quick Response Code Indonesia Standard，常读作 “Kris”。它是 Bank Indonesia 与支付系统行业共同制定的印尼国家级二维码支付标准，用于统一不同支付服务提供方的 QR 支付受理方式。Bank Indonesia 官方页面明确说明，所有提供 QR Code 支付的 Payment Service Provider（PSP）都必须使用 QRIS。

原文中”Quick Response Indonesian Standard”的写法不准确，应改为 Quick Response Code Indonesia Standard。

QRIS 的关键点：

  • 支持同一个 QR Payment Code 被不同支付工具和不同 PSP App 使用。
  • 支持 MPM 和 CPM 两种模式。
  • MPM 又包括静态 MPM 和动态 MPM：静态码通常由消费者输入金额；动态码通常由商户设备或系统生成，并包含金额或订单信息。
  • 资金来源可以是银行账户，也可以是 debit card、credit facility 或服务器型电子货币等，具体以印尼监管和 PSP 支持范围为准。
  • 支持 QRIS Cross-Border，用于与泰国、马来西亚、新加坡等伙伴国家或地区的跨境 QR 支付互联。

官方介绍：

  • Bank Indonesia: Quick Response Code Indonesia Standard (QRIS)
